RAG hybride pour l’analyse de rapports financiers 10-K (GAFAM)

Système de question-réponse ancré dans des filings SEC — retrieval hybride texte + roadmap données tabulaires (text-to-SQL) et routing intelligent.

Auteure : Sara El Harti Profil : Master 1 Data Science × Financial Engineering Type : projet personnel d’ingénierie RAG de bout en bout Corpus : 5 Form 10-K (Apple, Amazon, Alphabet, Meta, Microsoft)

Problématique & objectif

Les rapports 10-K mêlent narratif dense (facteurs de risque, MD&A) et états financiers chiffrés. Un LLM seul hallucine ; une recherche purement lexicale rate les paraphrases. Ce projet construit un RAG (Retrieval-Augmented Generation) qui récupère les passages pertinents puis génère une réponse citée, avec une architecture évolutive vers l’interrogation SQL des tableaux.

Architecture produit (3 versions)

V1 livrée RAG texte

Pipeline complet : extraction PDF → chunking → embeddings → Qdrant → recherche hybride (dense + BM25, fusion RRF) → rerank optionnel → génération locale (Ollama) → UI Streamlit → évaluation RAGAS.

V2 Module tabulaire

Données financières structurées dans DuckDB ; questions chiffrées via text-to-SQL (sans routing auto). Complète le RAG là où les tableaux cassent le chunking texte.

V3 Orchestration

Function calling : le système choisit texte, SQL, ou les deux, puis fusionne les réponses. Un seul point d’entrée pour l’analyste.

Valeur pour un recruteur

Maîtrise NLP/LLM appliquée à la finance, retrieval moderne, eval, produit démo, et vision claire données non structurées ↔ structurées.

V1 — pipeline technique (réalisé)

1. Extraction Docling : PDF 10-K → Markdown structuré (titres, blocs).
2. Chunking Hybride : coupe sur titres Markdown, puis taille max + overlap.
3. Index Embeddings BGE-small (384-d) ; Qdrant local (cosine) + meta entreprise/section.
4. Réponse Hybride RRF ± rerank MiniLM ; Ollama qwen2.5:3b ; démo Streamlit ; RAGAS.

Choix clés : recherche hybride pour corriger les faux amis sémantiques (ex. « supply agreements » vs risques supply chain) ; génération locale pour un déploiement sans coût API ; filtre par ticker/entreprise pour limiter le bruit cross-GAFAM. Échelle indicative V1 : ~2 200 chunks indexés sur 5 filings.

Stack & livrables

Stack : Python · Docling · sentence-transformers (BGE) · Qdrant · rank-bm25 · Ollama · Streamlit · RAGAS · (Claude API optionnelle) · DuckDB prévue en V2  |  Livrables : code modulaire (extraction, chunking, embeddings, indexing, retrieval, generation, evaluation) · interface démo · dataset d’éval · one-pager

Limites assumées & apprentissages

  • Tableaux financiers fragiles en V1 texte → motivent explicitement la V2 SQL.
  • Reranker léger (MiniLM) parfois inférieur à l’hybride RRF seul — d’où l’intérêt de mesurer (RAGAS).
  • Juge RAGAS local (petit LLM) : scores indicatifs, utiles pour itérer, pas comme benchmark labo.
